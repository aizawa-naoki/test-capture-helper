# test-capture-helper

UWSCR（UWSCの互換スクリプト実行ツール）を利用した、画面テスト用の簡易キャプチャ支援ツールです。

画面テストのエビデンス作成時、キャプチャファイルの「手動での名前変更」や「フォルダ分け」にかかる手間を削減し、キーボード操作だけでスムーズにテストケースごとのフォルダ管理・連番保存を行います。

---

## 主な特徴

1. **フォルダの自動作成・管理**
   * 設定ファイルで定義した規則（例：`TestCaseNo{testCaseNo}_Run{testTimes}`）に従い、自動でフォルダを作成し、その中にキャプチャを保存します。
2. **自動連番での保存**
   * 保存先フォルダ内のファイルを自動判定し、`001.png`、`002.png` のような3桁の1始まりの連番で重複なく保存します。

---

## 動作環境

* **Windows 10 / 11**
* **UWSCR** (バージョン 1.1.0 以降を推奨)
  * [UWSCR GitHub リポジトリ](https://github.com/stuncloud/UWSCR) よりダウンロードするか、以下のwingetで入手してください。  

    ```powershell
    winget install --id stuncloud.uwscr
    ```

---

## セットアップ

1. 本リポジトリの以下の2つのファイルを、適当なフォルダに配置します。
   * `capture-helper.uws`
   * `capture-helper.ini`
2. UWSCRで `capture_soft.uws` を実行します。
   * 例（コマンドプロンプトやPowerShell等から実行する場合）:
     ```powershell
     uwscr capture_soft.uws
     ```

---

## ⚙ 設定ファイル（`settings.ini`）の構成

`settings.ini` を編集することで、初期のフォルダ構造やファイル拡張子を変更できます。

```ini
[Settings]
; 保存先フォルダのベースディレクトリ（相対パス、絶対パスどちらも利用可能です）
; このフォルダ配下に、FolderFormatで指定する形式のフォルダが作成され、その中に連番で画像が保存されます。
BaseDir=save\evidence

; 保存先フォルダ名のフォーマット
; {testTimes} はテスト回数、{testCaseNo} はテストケース番号（自動で2桁のゼロ埋めになります）に置換されます
FolderFormat={testTimes}回目_テストケース{testCaseNo}

; 保存する画像の拡張子（png, jpg, bmp が利用可能です）
Extension=png

; スクリプト起動時の初期値（実行中に変更された値は、終了時に上書き保存できます）
testTimes=1
testCaseNo=1
```

## ⌨ キー操作一覧

ツール起動中、画面左上の吹き出しで現在の状態を確認しながら以下のキーで操作します。

| キー | 動作 |
| :--- | :--- |
| **`↑` キー** | テストケース番号 (`testCaseNo`) を **+1** します。 |
| **`↓` キー** | テストケース番号 (`testCaseNo`) を **-1** します（1未満にはなりません）。 |
| **`→` キー** | テスト回数 (`testTimes`) を **+1** します。 |
| **`←` キー** | テスト回数 (`testTimes`) を **-1** します（1未満にはなりません）。 |
| **`Ctrl + F1`** | **アクティブウィンドウ**をキャプチャし、連番で保存します（保存時ビープ音が鳴ります）。 |
| **`Ctrl + F2`** | **全画面**をキャプチャし、連番で保存します（保存時ビープ音が鳴ります）。 |
| **`ESC` キー** | ツールを終了します。終了時に、現在の進捗状態を `settings.ini` に上書き保存するか確認のダイアログが表示されます。 |

## 知っておくと便利な知識

* **管理者権限での実行について**  
  テスト対象のアプリケーション（ブラウザや自作アプリなど）が管理者権限で実行されている場合、このツールも「管理者として実行」していないと、キー入力の検知やアクティブウィンドウのキャプチャ（`Ctrl + F1`）が正しく機能しない場合があります。その際は、UWSCR（またはコマンドプロンプト等）を管理者として起動した上で実行してください。
